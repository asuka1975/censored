# プロダクト要求

Censored の **WHAT FOR** を置く。誰のために何を実現するか。機能の振る舞いはテストが正本なのでここには書かない。

**状態は草案。** 決まったことは本文に、決まっていないことは [未決事項](#未決事項) に書く。決まったものから本文に移し、未決事項から消す。

Censored は、AI で「ホワイト化」された SNS である。

## 誰のための SNS か

- SNS で暴言を吐いてしまう人
- SNS で暴言を吐かれたくない人

## 解決すること

既存の SNS は、投稿する文章を自由に考えられるからこそ、暴言や誹謗中傷が飛び交う殺伐としたものになっている。

Censored は、文章を書く自由を制限し、言いたいこと(トピック)を言える状態は保つ。alignment された AI がトピックに基づく文章の候補を出し、利用者はその中から選ぶ。AI は利用者のブラウザの中で動く([AI を動かす場所](#ai-を動かす場所と出所))。

## 核となる制約

利用者は自分で文章を書けない。投稿は、返信を含めて、次の流れでだけ作られる。

1. 利用者が、投稿したいトピックを 20 文字以内で入力する。
2. alignment された AI(利用者のブラウザの中で動く LLM)が、トピックに基づく文章の候補を 3 つ生成する。トピックが暴言のときは、穏当に言い換えた候補にする。
3. 利用者が候補から 1 つを選んで投稿する。選ばずに破棄することもできる。

返信では、手順 2 で元の投稿も AI に渡す。

候補は手直しできない。再生成の操作はない。

投稿をキャンセルしたあとで同じ内容で投稿し直せば、事実上は再生成できる。これは許容する。防ぐことは要件にしない。

制約の対象は投稿である。ユーザー名と自己紹介は対象外で、利用者が自由に入力できる。

## AI を動かす場所と出所

候補の生成は、利用者のブラウザの中で LLM を動かして行う。WebGPU を使い、使えない環境では WASM で動かす。サーバーは LLM を動かさない。

**サーバーは、投稿の文章が AI の出力かを確かめない。** 出所は公式 UI だけで守る。公式 UI の外から API を直接呼べば、誰でも任意の文章を投稿できる。最初の版では、この迂回を許容する(決定: 2026-11-03)。サーバーは、届いた本文の形式(空でないこと、140 文字以内であること)だけを検証して保存する。

WebGPU も WASM も使えない環境では、候補を生成できないので、投稿と返信はできない。

モデルとランタイムは、動かして比べてから決める([#16](https://github.com/asuka1975/censored/issues/16))。

20 文字の数え方(空白、絵文字、結合文字の扱い)はここに書かない。最初の機能の受け入れ条件とテストが正本である([NFR-I18N-3](../nfr/catalog.md))。

## 最初に作る機能

投稿、タイムライン、フォロー、返信。それ以外は最初の範囲に含めない。

## やらないこと

- 利用者が本文を直接入力して投稿する経路を設けない。
- 候補の再生成の操作を設けない。
- 候補の手直しを許さない。
- 事実上の再生成を防ぐ仕組みを設けない。
- 投稿にトピックを併記しない。
- サーバーで LLM を動かさない。
- 投稿の文章が AI の出力かを、サーバーで検証しない。

## 想定する規模

登録者は 1 万人。日次のアクティブな利用者は登録者の 1 割(1,000 人)と仮定する。アクティブな利用者 1 人が 1 日に平均 5 投稿する。1 日に約 5,000 投稿、平均で毎秒 0.06 件ほどになる。

1 割は仮の値で、実測できたら置き換える。

候補の生成は利用者のブラウザで行うので、生成の回数はサーバーの負荷にならない。サーバーが受けるのは、投稿と返信の作成と、タイムラインの読み取りである。投稿のピークは未決(未決事項 1)。

[非機能要件カタログ](../nfr/catalog.md) の数値は、この規模に照らして見直す。
