# ADR-0006: プロジェクトのライセンス

- Status: Accepted
- Date: 2026-11-02
- Deciders: asuka1975

## 背景

プロジェクトは OSS として公開する方針である。sydtest の利用条件を満たすには、テスト対象が **OSI 承認ライセンス** でなければならない([ADR-0004](0004-test-stack-and-mutation.md))。決定がないと、`check-licenses` はパッケージが存在する時点で失敗する。

依存(BSD-3-Clause と MIT が中心)はどの候補とも両立する。sydtest はテスト時のみの利用で配布物に含まれない。

## 決定

AGPL-3.0-or-later を採用する。`LICENSE` に全文を置き、`tools/policy/licenses.json` の `project` に SPDX 識別子を宣言する。

Censored はサーバーとして提供されるソフトウェアなので、GPL では改変版をホスティングする者にソースの公開義務が生じない。AGPL はこの抜け穴を塞ぐ。Mastodon など同種の OSS SNS でも採用例がある。

## 検討した代替案

### 案 A: AGPL-3.0-or-later(採用)

ネットワーク越しの利用にもソース公開を求める。欠点は、企業の利用や、将来の別ライセンスでの提供に制約が生じること(著作権者の整理が必要)。

### 案 B: MIT または Apache-2.0

採用の障壁が最も低い。Apache-2.0 は特許の条項を持つ。**却下理由:** 改変版を非公開で運営できるので、コミュニティへの還元を期待しないなら適切だが、Censored の分岐を防げない。

### 案 C: GPL-3.0-or-later

**却下理由:** サーバー側の利用では配布が発生せず、コピーレフトがほぼ働かない。

### 案 D: OSI 非承認のライセンス(BSL、SSPL など)

商用の競合を制限できる。**却下理由:** OSI 承認ではないので sydtest の利用条件を満たさなくなる。

## 結果

- `LICENSE` の本文が `project` の宣言と対応すると、`check-licenses` の DEP-8 が通る。本文の全文一致までは検査しない。
- 利用者向けにソースの入手先を提示する機能が要件に加わる(NFR-LIC-1)。

## 再検討の条件

- 外部からの貢献を受け入れると変更が難しくなる。受け入れる前に、CLA / DCO の要否とあわせて見直す。
