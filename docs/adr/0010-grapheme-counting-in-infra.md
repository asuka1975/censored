# ADR-0010: 書記素の数え方を infra に置き、ICU の IO 版を保持付きで呼ぶ

- Status: Accepted
- Date: 2026-11-02
- Deciders: asuka1975

## 背景

[ADR-0009](0009-grapheme-counting.md) は、書記素の数を `text-icu` の `breakCharacter` で数え、ICU に触れるコードを `censored-domain` の 1 モジュールに置くと決めた。実装の検証で、この置き方では正しく数えられないことが分かった。

2026-11-02 に、GHC 9.10.3、ICU 74.2、`text-icu` 0.8.0.5 で次を検証した。

- `text-icu` の純粋な `breaks`(ADR-0009 の実装)は、入力が大きいと誤った数を返す。`a` を 300,000 個並べた入力は、5 回の実行のすべてで 300,000 より小さい数(296,081 など)を返した。国旗 300,000 個は、正しい数の 5 倍以上(1,566,915 など)を返した。実行中に GC を起こさない設定(`+RTS -A2g`)にすると、正しい数になった。
- IO 版の API(`Data.Text.ICU.Break` の `breakCharacter` と `next`)でも、反復器を保持しないと誤る。反復中に GC を強制して `a` 300,000 個を数えると、5 回中 5 回が誤りだった(299,934 など)。国旗では再現しなかった。
- IO 版で、反復器を `keepAlive#` で反復の終わりまで保持すると、誤りは出なかった。`a` 300,000 個を 10 回、国旗 300,000 個を 10 回、`a` 1,000,000 個を 5 回で、いずれも GC を強制している。
- 原因は、ソースの読みと上の実験からの推定である。`breaks` は `unsafePerformIO` の中で反復器を作り、遅延リストで反復する。`BreakIterator` は入力のコピーを `brText`、ICU の反復器を `brIter` に持つ。反復中に使われるのは `brIter` で、`brText` を保持するものが無いので、GC が入力のコピーを解放し、ICU が解放済みのメモリを読むと考える。確かめたのは、反復器を保持すると誤りが消えることまでである。
- 小さい入力でも、低い頻度で同じ誤りが起き得る、というレビュアーの報告がある(20 文字の入力を 4 スレッドで数え、別スレッドから GC を繰り返し、最初の 1 回の 80,000 回の試行で 1 回の不一致)。本セッションでは再現していない。
- 純粋な `breaks` はリストを実体化する。レビュアーの測定では、1,000 万文字で約 1.6 GB のメモリを使った。
- `domain` に `IO` は置けない。`check-source` の DIR-3 が `IO` の使用を拒否し、抑止する手段がない。HLint も `unsafePerformIO` を禁止している。

## 決定

書記素の数は、`text-icu` の IO 版の API(`breakCharacter` と `next`)で数える。反復器は `keepAlive#` で反復の終わりまで保持する。この呼び出しは `censored-infra` の 1 モジュールに置き、`Text -> Int` の純粋な関数として公開する。純粋に見せるための `unsafePerformIO` と、HLint の禁止の抑止は、このモジュールの 1 か所に限る。

`censored-domain` は ICU に触れず、文字数を数える関数を引数で受け取る。受け渡しの形は asuka1975/censored#2 で決める。`domain` の許可リストから `text-icu` を外す。

`text-icu` の選定と、ICU の前提(開発環境、CI、実行環境)は、ADR-0009 のとおりとする。

## 検討した代替案

### 案 A(採用): infra に置き、IO 版を保持付きで呼ぶ

ADR-0009 のライブラリの選定を維持できる。`domain` の純粋性([ADR-0002](0002-monorepo-and-package-boundaries.md))と DIR-3 を保つ。IO のループは定数のメモリで済み、リストを実体化しない。反復中に GC を強制するテストを書ける。

欠点は 3 つある。純粋に見せるための `unsafePerformIO` が 1 か所残ること。`keepAlive#` で保持すれば足りるという前提が、`text-icu` の内部構造の理解に依存し、`text-icu` の更新で変わり得ること。#2 で `domain` に関数を渡す形になり、コンストラクタの形が複雑になること。

### 案 B: `domain` の 1 モジュールに IO 版を置く(ADR-0009 の置き方のまま)

**却下理由:** `check-source` の DIR-3 が `domain` の `IO` を拒否し、抑止する手段がない。通すにはゲートの変更が要り、ADR-0002 の純粋性の設計を崩す。

### 案 C: 純粋な `breaks` を使い続け、入力の大きさを制限する

**却下理由:** 小さい入力でも低い頻度で誤りが起き得るという報告があり、上限を決めても安全にならない。原因は解放済みメモリの読み取りなので、結果が違うだけでなく、クラッシュし得る。

### 案 D: 効果を持つ Port(`Text -> IO Int`)にして、文字数の検査を application に置く

**却下理由:** 不正な値を型の境界で弾く(`.claude/rules/haskell.md`)ことを `domain` で保証できなくなる。トピックと候補の上限が、`domain` の型でなく、use case の検査になる。

### 案 E: `unicode-data` と自前の規則(ADR-0009 の案 B)

FFI と C ライブラリをなくせる。ADR-0009 では規模を理由に退けたが、この欠陥で利点が相対的に大きくなった。**却下理由:** 書記素の規則の実装と、性質のデータの生成器が要る(`unicode-data` には必要な性質がない)。Unicode の版ごとの更新も自前になる。案 A でさらに問題が起きたときの移行先として残す。

### 案 F: `base` だけで近似する(ADR-0009 の案 C)

**却下理由:** 書記素への準拠が近似にとどまり、NFR-I18N-3 の「正しく扱う」を満たす保証がない。

## 結果

- 純粋に見せる `unsafePerformIO` が、`censored-infra` に 1 か所残る。入力の `Text` だけに依存し、ICU のデータは読み取り専用で、反復器は呼び出しごとに作るので、見かけの純粋性は保たれると考える。
- 反復中に GC を強制するテストを infra に置く。保持を外すと落ちることを確かめる。GC の起き方に依存するので、不安定にならないよう、回数と大きさを固定する。
- infra はミューテーションテストの対象外である(`tools/policy/mutation.json` は `domain` と `application` だけ)。数え方の検証は、例示、プロパティ、GC の強制テストに頼る。
- `domain` の許可リストから `text-icu` を外す(`tools/policy/layers.json`)。ゲート設定の変更なので、製品コードとは別の PR にして、人間が承認する。
- 純粋な `breaks` と `breaksRight` を誤って使わないよう、HLint で禁止する。これもゲート設定の変更なので、別の PR にする。
- ICU の導入手順(`libicu-dev` と `pkg-config`)と、実行環境の ICU の追跡(asuka1975/censored#3)は変わらない。
- ADR-0009 は `Superseded by ADR-0010` になる。この ADR を Accepted にする際に、人間が行う。ADR-0009 を参照している依存の台帳と用語集は、この ADR の参照に直す。

## 再検討の条件

- 反復器を保持しても、GC を強制したテストで誤りが再現したとき。
- `text-icu` が更新されて、純粋な API の欠陥が直ったとき。案 A の `unsafePerformIO` を外せるか見直す。
- `text-icu` に未修正の脆弱性が報告されたとき、または GHC の更新でビルドできなくなったとき。案 E に移る。
- #2 で、`domain` に関数を渡す形が複雑すぎると分かったとき。
