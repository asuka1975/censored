# ADR-0001: 情報配置の原則と機械強制

- Status: Accepted
- Date: 2026-11-02
- Deciders: asuka1975(追認)

## 背景

AI が実装の大半を書く開発では、説明的なコメントや重複した文書が短時間で大量に生まれる。同じ事実が複数の場所に書かれると、どれが正しいか分からなくなる。また、文章だけの規約は AI のコンテキストから外れた瞬間に守られなくなる。

## 決定

情報の種類ごとに置き場所を一つに定める。コードは HOW、テストは WHAT、コミットログは WHY、コメントは WHY NOT、ADR は WHY THIS とする。

機械で判定できる規則は機械で判定し、すべての規則に ID を振る。Haddock は API 契約としてコメント規則の例外とし、責務と、型で表せない条件だけを書く。

## 検討した代替案

### 案 A: 置き場所の固定と機械強制(採用)

判定が明確で、AI にも人にも同じ基準が働く。コメントにタグを必須にすることで、書く前に理由を問う効果がある。欠点は、タグの有無しか検査できず、中身の質はレビューに依存すること。

### 案 B: 文章の規約のみ

導入は最も簡単。**却下理由:** AI のコンテキストに入らなければ効果がなく、違反の検出が人間の注意力に依存する。

### 案 C: コメント全面禁止

コードで説明し切る方針。**却下理由:** 「なぜ自明な別解を採らなかったか」はコードに表せず、次の変更者が同じ失敗を繰り返す。

### 案 D: Haddock も WHY NOT のみに制限

規則は単純になる。**却下理由:** ライブラリの利用者が実装を読まずに使うための事前条件や法則を書く場所がなくなる。

## 結果

- `check-source`、`check-commits`、`check-adr` などの保守が必要になる。
- タグの形式に従う手間が増える。
- 違反の出力が機械可読なので、AI が自力で修正できる。

## 再検討の条件

- タグ付きの言い換えコメントがレビューで頻繁に指摘されるようになったら(タグが形骸化している)。
- 抑止の件数が増え続けるようになったら(規則が現実に合っていない)。
