# ADR-0002: モノレポとパッケージ境界によるレイヤ強制

- Status: Accepted
- Date: 2026-11-02
- Deciders: asuka1975

## 背景

バックエンド(Haskell)とフロントエンド(PureScript)は言語が異なるが、API 契約を共有する。AI が変更を行うとき、層の境界は明示的に強制しないとすぐに侵食される。

検証では次を確認した。

- `cabal.project` の `program-options` でローカルパッケージ全体に `-Werror` を適用できる。
- Spago のワークスペースで複数パッケージを扱え、`pedanticPackages` が宣言の過不足を検出する。

## 決定

1 リポジトリに `backend/`、`frontend/`、`contract/` を置く。層は 1 パッケージに対応させ、依存方向はパッケージの依存関係で強制する。層の一覧と許可される依存は `tools/policy/layers.json` に置き、`check-layers` で検証する。domain は外部依存も許可リスト制とし、IO を持ち込む型は `check-source` で検出する。

## 検討した代替案

### 案 A: モノレポ + 層ごとのパッケージ(採用)

依存方向の違反がコンパイルエラーになる。欠点は、モジュールの移動にパッケージの宣言変更が伴うことと、パッケージをまたぐカバレッジの統合が必要になること。

### 案 B: 単一パッケージ + HLint の import 制限

設定が少なく、ビルドも速い。**却下理由:** ファイルと設定を編集すれば越えられ、違反がコンパイルでは止まらない。

### 案 C: Cabal の内部ライブラリ(sublibrary)

1 ファイルで境界を持てる。**却下理由:** ミューテーションのドライバはパッケージ単位で `--suite-pkg` を受け取る設計で、この構成では検証していない。また HLS やツールの対応に差がある。

### 案 D: 言語ごとにリポジトリを分割

権限と CI を分離できる。**却下理由:** API 契約の変更が複数リポジトリにまたがり、AI のコンテキストも分断される。

## 結果

- 層をまたぐ機能追加では複数の `.cabal` を編集する。
- `.cabal` の共通設定を共有できないので、警告は `cabal.project` に集約する。
- `censored-testkit` を介してテスト用の部品を共有する。

## 再検討の条件

- 全体のビルド時間がパッケージ数を理由に開発を妨げるようになったら。
- フロントエンドとバックエンドでチームが分かれ、権限の分離が必要になったら。
