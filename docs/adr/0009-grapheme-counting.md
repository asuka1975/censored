# ADR-0009: 書記素単位の文字数の数え方

- Status: Superseded by ADR-0010
- Date: 2026-11-02
- Deciders: asuka1975

## 背景

トピックは 20 文字以下、候補(投稿の本文)は 140 文字以下とし、文字数は見た目の 1 文字(書記素)で数える(asuka1975/censored#1、#2)。NFR-I18N-3 は文字数の定義の明示と、絵文字や結合文字の正しい扱いを求めている。

書記素の数はコードポイントの数と異なる。`Text` の長さはコードポイントの数なので、標準ライブラリだけでは数えられない。

2026-11-02 に、GHC 9.10.3、ICU 74.2(Ubuntu 24.04 の標準)で次を検証した。

- `text-icu` 0.8.0.5 の `breakCharacter`(ロケール `Root`)は、拡張書記素クラスタ(UAX #29)で分割する。次の入力を、書記素 1 つと数えた。
  - 国旗(コードポイント 2 つ)
  - 家族の絵文字(ZWJ で結んだ、コードポイント 5 つ)
  - `e` と U+0301(コードポイント 2 つ)
  - `か` と濁点 U+3099
  - 肌の色付きの手
  - ハングルの L + V + T
- 国旗 20 個は 20、21 個は 21 と数えた。
- `a` に U+0301 を 1000 個重ねた文字列は、書記素が 1、コードポイントが 1001 だった。書記素の数の上限だけでは、入力の大きさを抑えられない。
- ICU のヘッダ(`libicu-dev`)がある環境では、`text-icu` 0.8.0.5 が GHC 9.10.3 でビルドできた。ヘッダが無い環境では、ソルバーが `text-icu` 0.7.1.0 と `text` 1.2.5.0 に黙って後退した。0.8.0.5 は `pkgconfig-depends: icu-i18n >= 62.1` を要求するため。
- `text-icu` 0.8.0.5 の推移依存は `bytestring`、`deepseq`、`text`、`time` で、すべて GHC に同梱されている。ライセンスは BSD-3-Clause(許可リストにある)。
- `text-icu` 0.8.0.5 の公開は 2024-04-06(Hackage の索引の記録)で、これが最新版である。`.cabal` の改訂は 2025-03 と 2026-01 にある。依存の導入基準「18 か月以内にリリースがある」を満たさない。
- `unicode-data` 0.9.0(Apache-2.0、2026-09 公開)のソースには、`Grapheme_Cluster_Break` と `Extended_Pictographic` に関する記述が見つからなかった。

未検証のこと。

- GitHub の `ubuntu-24.04` ランナーに `libicu-dev` があるか。
- ICU の版が違うと、新しい絵文字の数え方が環境ごとに変わるか(推測)。

## 決定

書記素の数は `text-icu` の `breakCharacter`(ロケール `Root`)で数える。ICU に触れるのは `censored-domain` の 1 モジュールだけにし、ほかのモジュールと層は ICU に依存しない。`censored-domain` の `.cabal` に `text-icu` の下限(0.8 以上)を書き、ソルバーの後退を防ぐ。開発環境と CI は `libicu-dev` と `pkg-config` を前提とする。依存の台帳での tier は `standard` とする。

## 検討した代替案

### 案 A(採用): `text-icu`

Unicode の規則(UAX #29)を実装しており、規則の表を自分たちで持たなくてよい。検証した例をすべて期待どおりに数えた。推移依存は GHC 同梱のものだけである。

欠点は 3 つある。システムライブラリ(ICU)が開発環境、CI、実行環境に要ること。導入基準の保守の項目を満たさないこと。ICU の版に結果が依存し得ること。

### 案 B: `unicode-data` と自前の規則の実装

システムライブラリが要らず、結果が環境によらない。`unicode-data` は活発に保守されている。**却下理由:** 書記素の規則に必要な性質のデータが `unicode-data` に見つからず、規則の実装と表の生成器を自前で持つことになる。Unicode の版ごとの更新も自前になる。20 文字と 140 文字の上限のために持つ負担として大きすぎる。案 A で問題が起きたときの移行先として残す。

### 案 C: `base` だけで近似する

依存もシステムライブラリも増えない。規模も小さい。**却下理由:** 書記素への準拠が近似にとどまり、NFR-I18N-3 の「正しく扱う」を満たす保証がない。

### 案 D: コードポイントの数で数える

依存が増えない。**却下理由:** 国旗や家族の絵文字、結合文字が複数文字に数えられる。プロダクトが見た目の 1 文字で数えると決めている(asuka1975/censored#1)。

## 結果

- 開発環境と CI に `libicu-dev` と `pkg-config` が要る。`make setup` はシステムに触れない方針なので、導入は利用者の手順になる。前提が満たされないときにソルバーが古い版へ後退しないよう、`.cabal` の下限で防ぎ、セットアップで `icu-i18n` の有無を検査して失敗させる(GATE-1)。検査の追加と CI の変更は `tools/` と `.github/` の変更なので、製品コードとは別の PR にして、人間が承認する。
- `domain` の外部依存の許可リスト(`tools/policy/layers.json`)に `text-icu` を足す。これもゲート設定の変更なので、別の PR にする。
- 実行環境にも ICU の共有ライブラリが要る。デプロイの構成は未決定なので、決まったときに実行環境のイメージへ含める。
- 依存の導入基準のうち、保守の項目を満たさないことを、この ADR の例外として受け入れる。
- ICU の版による数え方の差を受け入れる。テストで固定するのは、Unicode で長く安定している入力(国旗、ZWJ の家族の絵文字、結合文字)に限る。
- 書記素の数の上限とは別に、コードポイントの数(またはバイト数)の上限が要る。NFR-ABUSE-3 のため。値は asuka1975/censored#2 の受け入れ条件で決める。

## 再検討の条件

- GHC の更新([ADR-0003](0003-toolchain-and-lint-stack.md) の手順)で `text-icu` がビルドできなくなったとき。
- `text-icu` に未修正の脆弱性が報告されたとき。
- ICU の版の違いで、CI と本番が同じ入力に異なる数を返したとき。
- 実行環境への ICU の導入が運用上の負担になったとき(案 B に移る)。
