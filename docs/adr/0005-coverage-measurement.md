# ADR-0005: カバレッジの計測方法

- Status: Accepted
- Date: 2026-11-02
- Deciders: asuka1975

## 背景

Haskell と PureScript で計測の仕組みが異なるが、ゲートは同じ基準で判定したい。

**c8 を PureScript に適用したところ、誤った結果になった。** `summarize` を一度も呼ばないテストに対し、c8 12.0.0 は `PostBody.purs` を行・分岐・関数すべて 100% と報告した。一方で V8 の生データには `"summarize" 925:1332:0`(未実行)が正しく記録されていた。purs の出力するソースマップが疎で、v8-to-istanbul の変換で未実行の範囲が失われていると考えられる(原因の詳細は未調査)。

Haskell では次を確認した。

- `hpc-codecov` は LCOV を出力でき、`hpc sum --union` で統合した tix を処理できる。
- 派生インスタンス(`deriving stock`)の行が未実行として数えられる。
- テストから読み込まれないモジュールは tix に現れない。

## 決定

判定の単位を行に統一し、両言語とも LCOV に変換して `check-coverage` で判定する。Haskell は `hpc sum` + `hpc-codecov`。PureScript は `NODE_V8_COVERAGE` の生データを `ps-coverage` でソースマップから PS の行に射影する。

偽の合格を防ぐため、`src/` の全ファイルと LCOV を突き合わせ、現れないモジュールを不合格にする。下限は層ごとに `tools/policy/coverage.json` で定め、PR の変更行にも下限を設ける。

## 検討した代替案

### 案 A: V8 の生データを自前で射影(採用)

約 100 行で書け、結果を検証できる。欠点は保守が自分たちの責任になることと、精度がソースマップの細かさに制限されること(宣言行は分母に入らない、1 行内の部分的な実行は区別しない)。

### 案 B: c8

一般的で設定だけで済む。**却下理由:** 実際に誤った 100% を報告した。カバレッジゲートにとって最悪の故障である。

### 案 C: 出力 JS の行で判定

ソースマップが不要。**却下理由:** PR の変更行(PS)と対応づけられず、差分カバレッジが使えない。生成コードも分母に入る。

### 案 D: Codecov などの外部サービス

差分カバレッジとグラフが得られる。**却下理由:** 手元で再現できないゲートを作らない方針に反する。可視化が必要になったら LCOV を送るだけで追加できる。

### 案 E: 全体の一律の下限

単純である。**却下理由:** 純粋層の高い基準と IO 層の現実的な基準を両立できない。

## 結果

- PureScript の数字は JS への変換を経るので、Haskell と厳密には同じ意味にならない。層ごとの下限で吸収する。
- `ps-coverage` のテストを保守する。
- 下限は初期値で、実績がない。

## 再検討の条件

- c8 または purs のソースマップが改善され、未実行の関数を正しく報告するようになったら。
- PureScript に公式のカバレッジツールが現れたら。
- 下限を満たすためだけのテストが目立つようになったら(ミューテーションの比重を上げる)。
