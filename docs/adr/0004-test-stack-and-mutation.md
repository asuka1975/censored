# ADR-0004: テスト基盤とミューテーションテスト

- Status: Accepted
- Date: 2026-11-02
- Deciders: asuka1975

## 背景

AI が実装を書く開発では、テストの強さが品質の上限を決める。カバレッジは「実行したか」しか測らず、アサーションのないテストでも上がる。

調査の範囲では、Haskell で現役のミューテーションテストは `sydtest-mutation-plugin` のみだった(MuCheck は依存が古いまま)。Cabal と GHC 9.10.3 で実際に動かした結果は次の通り。

- `mkPostBody` の上限判定に対し、500 文字ちょうどのテストがないことを `>` → `>=` の生存で検出した。
- テストのない `summarize` を uncovered として検出した。
- 複数パッケージをまたいで動作し、`--diff` で変更箇所に限定できる(`selected 3 / killed 3`)。

検証で判明した制約は次の通り。

- ビルドキャッシュが効くとマニフェストが空になり、**0 件で合格する**。
- テストスイート名が複数パッケージで同じだと `DuplicateSuiteName` で停止する。
- `-Werror` と共存しない(計器のパッケージが未使用扱いになる)。
- POSIX ロケールでは日本語のテスト名が子プロセスの引数で壊れて失敗する。UTF-8 ロケールが必須である。

sydtest のライセンスは独自で、次のいずれかが利用条件である。

- テスト対象を商用利用しない
- テスト対象が OSI 承認ライセンスの OSS である

本プロジェクトは OSS として公開する方針なので後者を満たす([ADR-0006](0006-project-license.md))。sydtest の推移依存 `opt-env-conf` は LGPL-3.0-only である。テストのバイナリにしかリンクしないので配布の義務は生じない。製品に含まれないことは `check-licenses` が依存グラフで検証する。

PureScript には専用のツールがない。Stryker 10 の command ランナーで出力 JS を変異させる方式は動作した。ただし生のスコアは `derive` の生成コードなどで大きく下がる(例: 45%)。

## 決定

Haskell のテストは sydtest + hedgehog(`sydtest-hedgehog`)とする。ミューテーションは `sydtest-mutation-driver` を `hs-mutation` から駆動し、PR では変更箇所の生存を不合格、夜間は全体のスコアを判定する。

PureScript のテストは spec + spec-node + quickcheck とする。ミューテーションは Stryker を使い、`ps-mutation` がソースマップで PS の行へ戻し、宣言行と生成コードを除いて判定する。

対象は純粋層と application に限る。

## 検討した代替案

### 案 A: sydtest + mutation(採用)

Haskell でテストの強さを客観的に測れる唯一の現実的な手段。欠点は下の「結果」に書く。

### 案 B: hspec または tasty(ミューテーションなし)

ライセンスが BSD/MIT で、エコシステムが大きい。**却下理由:** テストの強さを測る手段がなくなり、AI が書いたテストの質をレビューの読解だけに頼ることになる。

### 案 C: MuCheck

**却下理由:** 依存が古く、現在の GHC でビルドできる見込みがない。

### 案 D: AI がレビュー時に手で変異を試す

ツール不要。**却下理由:** 実行ごとに結果がぶれる上、遅い。機械で同じことができるなら機械に任せる。

### 案 E: PureScript はミューテーションなし

ツールがなく手間も省ける。**却下理由:** フロントエンドのロジックだけ測れなくなる。Stryker の結果を行へ戻すだけで実用になった。

## 結果

- **ライセンスの条件に縛られる。** プロジェクトを非公開にするなら、個別契約かテスト基盤の移行が必要になる。`check-licenses` が `LICENSE` の本文と宣言の対応を検査する。
- sydtest は開発が活発で版が速く上がる(2026-05 の 0.24 から 2026-10 の 0.33 まで)。ミューテーション機能も 2026-05 に追加されたばかりである。freeze で固定し、更新は意図して行う。
- `.cabal` に `flag mutation` の定型が必要になる。
- 作者が 1 人のプロジェクトへの依存である。
- 等価ミュータントには `WHY NOT:` 付きの無効化が要る。

## 再検討の条件

- sydtest の開発が 6 か月止まったら。
- プロジェクトの公開方針が変わったら。
- PR のミューテーションが 15 分を超えるようになったら(対象や頻度を見直す)。
- 無効化の件数が生存の修正より多くなったら(ゲートが実情に合っていない)。
