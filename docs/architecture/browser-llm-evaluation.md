# ブラウザ内 LLM の評価の手順

[ADR-0012](../adr/0012-browser-llm-runtime.md) の計測の手順と、結果の記録。ランタイムとモデルを決めるための、人間が自分の端末で実行できる手順を書く([Issue #16](https://github.com/asuka1975/censored/issues/16))。

**結果の欄は、まだ空である。** 作成した環境では、モデルの置き場(`huggingface.co`、`cdn-lfs.huggingface.co`)と `cdn.jsdelivr.net` へ接続できず(ネットワーク方針が 403 で拒否)、GPU も無いため、計測できなかった。次の節の構成を、WebGPU を使える端末と、使えない端末で、実際に動かして埋める。

## 評価する構成

| # | ランタイム | モデル(量子化) | 経路 | 備考 |
| --- | --- | --- | --- | --- |
| 1 | transformers.js | Qwen3-0.6B(ONNX、q4) | WebGPU、WASM | 小さいモデルの基準 |
| 2 | transformers.js | Qwen3-1.7B(ONNX、q4) | WebGPU、WASM | |
| 3 | transformers.js | LFM3-1.7B(ONNX、q4) | WebGPU、WASM | #2 と同じ大きさの比較 |
| 4 | wllama | Qwen3-0.6B(GGUF、Q4_K_M) | WebGPU、WASM | |
| 5 | wllama | Qwen3-1.7B(GGUF、Q4_K_M) | WebGPU、WASM | |
| 6 | wllama | LFM3-1.7B(GGUF、Q4_K_M) | WebGPU、WASM | llama.cpp と wllama が LFM3 に対応するか未確認。GGUF が無い、または動かなければ、動かなかったと記録して省く |

モデルの選び方:

- 比べるモデルは Qwen3 と LFM3(人間の指示、2026-11-04)。Gemma は外した。
- Qwen3 は、公式の README が Apache 2.0 と書く。小型版(0.6B、1.7B)を使う。
- LFM3 は、Liquid の公式リポジトリ(cookbook)に `LFM3-1.7B` が出てくる。transformers.js の対応モデルに載る。`LFM3-1.7B` が日本語に対応することは、人間が確認した(2026-11-04)。ライセンスの条件は、確かめていない。**使う前に、人間が確認する。**
- ONNX と GGUF の配布の有無と、実際の大きさは、確かめていない。見つからないモデルは、別の同程度のモデルに替えて、記録する。
- WebLLM は、WebGPU でしか動かないので、基盤の候補にも、計測の対象にも含めない。

## プロンプトの草案

実装(#15)で見直す草案。計測では、すべての構成に同じプロンプトを使う。

```text
あなたは、投稿を穏当な日本語に整えるアシスタントです。
利用者が言いたいこと(トピック)を受け取り、同じ主張の核を保ったまま、攻撃的な言葉や人格への攻撃を避けた、短い投稿文を 3 つ作ります。
- 各投稿は 140 文字以内にする。
- 3 つの投稿は、言い回しを変える。
- 罵倒、差別、個人への攻撃は書かない。
- 返信先の投稿が与えられたときは、その内容に応える投稿にする。
- 出力は、文字列 3 つの JSON の配列だけにする。
```

## 計測の方法

1 つの構成と 1 つの経路ごとに、次を記録する。

| 項目 | 方法 |
| --- | --- |
| 端末 | CPU、GPU、メモリ、OS、ブラウザと版。WebGPU の有無(`navigator.gpu` が定義されているか) |
| ダウンロードの大きさ | ブラウザの開発者ツールの Network で、モデルと WASM の転送量の合計(MB) |
| 初回の読み込み時間 | キャッシュを空にして、ページを開いてから、生成できる状態になるまでの時間(秒)。回線の速さも書く |
| 2 回目以降の読み込み時間 | キャッシュがある状態で、同じ時間(秒) |
| 生成の時間 | トピック 1 件あたりの、最初のトークンまでの時間と、3 つの候補を得るまでの時間(秒)。各トピックを 3 回測り、中央値を取る |
| メモリ | ブラウザのタスクマネージャーで、生成中のタブのメモリ(MB) |
| 有効な出力の割合 | 14 件のうち、JSON として解釈でき、文字列がちょうど 3 つで、各 140 書記素以内だった件数 |
| 候補の質 | 下の採点。人間が採点し、出力そのものも記録する |

マルチスレッドの WASM(wllama)を測るときは、`Cross-Origin-Embedder-Policy: require-corp` と `Cross-Origin-Opener-Policy: same-origin` のヘッダーを付けた状態と、付けない状態の両方を測る。

端末は、少なくとも次の 3 種類を測る。

1. WebGPU を使える、GPU のある端末(デスクトップ)
2. WebGPU を使えない、または使わない、CPU だけの端末(WASM の経路)
3. 利用者の想定に近い、中程度のスマートフォン

## 候補の質の採点

各出力(3 つの候補)を、人間が 1〜5 で採点する。

| 観点 | 5 の基準 | 1 の基準 |
| --- | --- | --- |
| 穏当さ | 攻撃的な言葉も、人格への攻撃も無い | 罵倒がそのまま残る |
| 意味の保持 | トピックの主張の核が残っている | 別の話になっている |
| 日本語の自然さ | そのまま投稿できる | 文法が崩れている、意味が通らない |
| 3 つの違い | 言い回しが明確に違う | ほぼ同じ文 |

返信(#13、#14)は、返信先の投稿に応える内容かも見る。

## 判断の基準(提案)

数値は提案で、人間が決める。

| 基準 | 提案 |
| --- | --- |
| 有効な出力の割合 | 14 件のうち 12 件以上 |
| 候補の質 | 穏当さの平均が 4 以上。意味の保持と日本語の自然さの平均が 3.5 以上 |
| 初回の読み込み | WebGPU の端末で 60 秒以内、WASM の端末で 120 秒以内(回線 100 Mbps) |
| 2 回目以降の読み込み | 15 秒以内 |
| 3 つの候補を得る時間 | WebGPU の端末で 20 秒以内、WASM の端末で 60 秒以内 |
| ダウンロードの大きさ | 1.5 GB 以内 |

## 作成した環境で確かめられなかったこと

- モデルの重みを取得できない(`huggingface.co`、`cdn-lfs.huggingface.co`、`cdn.jsdelivr.net` が 403)。上の計測のすべてが、これに依存する。
- GPU が無く、WebGPU の計測ができない。
- LFM3 のライセンスの条件、llama.cpp と wllama の LFM3 への対応を、一次情報で確認できない。日本語への対応は、一次情報では確認できず、人間の確認(2026-11-04)による。
- MediaPipe の LLM Inference の文書(`ai.google.dev`)に到達できない。
