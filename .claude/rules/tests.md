# テスト

正本: `docs/conventions/05-test-quality-gate.md`

- テスト名は仕様の一文。条件と結果を書く。`501文字の本文を拒否する`
- 期待値はリテラルか独立した性質で書く。実装と同じ計算で作らない
- 結果と状態を検証する。内部の呼び出し回数を検証しない
- 境界は例示で固定する(上限ちょうどと上限 + 1)。純粋なロジックにはプロパティテストを使う
- 実時刻、待機、再試行(`flaky`)、無効化(`xit`、`pending`)を使わない
- **テストが落ちたら実装を直す。** テストを変えてよいのは仕様が変わったときだけ。そのときは理由をコミットに書く
