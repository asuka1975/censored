# ADR の起草

規約: `docs/conventions/10-adr.md`

## 手順

1. **ADR が必要か確かめる。** 規約の「いつ書くか」に当たらなければ、コメントの `WHY NOT:` かコミットログで足りる。

2. **番号を決める。** `docs/adr/` の最大の番号 + 1。欠番を作らない。

3. **`docs/adr/template.md` をコピーする。** ファイル名は `NNNN-短い-slug.md`(英小文字と数字とハイフン)。

4. **内容を書く。**
   - 背景: 事実を書く。検証したことと、推測を分ける
   - 代替案: 採用案を含めて 2 つ以上。不採用の案には `**却下理由:**` を書く
   - 結果: 悪いことも書く
   - 再検討の条件: 具体的な条件を書く

   **検証していないことを検証済みのように書かない。** 候補のツールが本当に動くか分からなければ、動かして確かめるか、未検証と明記する。

5. **Status は `Proposed` のままにする。** `Deciders` には決定する人間を書く。AI は Accepted にしない(ADR-9)。

6. **索引を更新する。** `docs/adr/README.md` の表に追加する。

7. **置き換える場合。** 古い ADR の Status 行を `Superseded by ADR-NNNN` に変える。本文は変更しない。

8. **`node tools/gates/check-adr.mjs` を実行する。**

9. **人間に判断を求める。** 何を決めてほしいかを、代替案の差とともに短く伝える。
