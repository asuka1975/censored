# レビューゲートの実行

規約: `docs/conventions/04-nfr-gate.md`、`docs/conventions/05-test-quality-gate.md`

## 手順

1. **前提を確認する。** 作業ツリーがコミット済みであること(`git status --porcelain` が空)。レビューは HEAD に対して行うので、未コミットの変更があれば止まる。`make check` が通っていなければ先に通す。

2. **基準を決める。** 既定は `origin/main`。`BASE=$(git merge-base origin/main HEAD)` で確認する。

3. **レビュアーを並列に起動する。** `nfr-reviewer` と `test-quality-reviewer` を、新しいコンテキストのサブエージェントとして同時に起動する。渡すのは次だけにする。
   - 基準のリビジョン
   - 受け入れ条件(Issue の本文をそのまま)

   **渡してはいけないもの:** 実装時の思考、計画の経緯、「ここは問題ない」という説明、前回の指摘への弁明。独立性がこのゲートの価値である。

4. **結果を確かめる。** 返ってきた記録の `sha` が現在の `git rev-parse HEAD` と一致することを確認する。一致しなければ再実行する。

5. **`fail` があれば修正する。** 指摘を読んで、実装 AI(自分)が修正し、コミットして 3 に戻る。レビュアーの判定を書き換えない。**3 周で合格しなければ止まって人間に報告する**(AI-7)。

6. **PR 本文に記録する。** 既存の `## レビューゲート記録` 節を今回の結果で置き換える。

   ```bash
   BODY=$(mktemp)
   gh pr view --json body -q .body > "$BODY"
   # 「## レビューゲート記録」以下を両レビュアーの出力で置き換える
   gh pr edit --body-file "$BODY"
   ```

   PR がまだなければ、作成時の本文に含める。

7. **検査する。** `make check-pr PR_BODY=<本文のファイル>` が通ることを確認する。

8. **報告する。** 両ゲートの判定と、人間が見るべき点(`n/a` にした観点、無効化したミュータント、参考の指摘)を伝える。

## 記録の扱い

記録はレビュアーの出力をそのまま貼る。**手で書いたり、判定を変えたりしない。** 技術的には防げないので、これは信頼の問題である。
